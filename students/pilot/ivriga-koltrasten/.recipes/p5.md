# p5.js

## When to use

Generative art, an animation loop, bouncing balls, particles, anything
where you want `setup()` / `draw()` and friendly helpers like
`ellipse(mouseX, mouseY, 50)` instead of writing your own render loop.

## Minimal working example

```html
<!doctype html>
<html lang="sv">
<head>
  <meta charset="utf-8">
  <title>fingerfärg</title>
  <style>html,body{margin:0;height:100%;overflow:hidden}</style>
  <script src="https://cdn.jsdelivr.net/npm/p5@1.11/lib/p5.min.js"></script>
</head>
<body>
  <main></main>
  <script>
    function setup() {
      createCanvas(windowWidth, windowHeight);
      noStroke();
    }
    function draw() {
      fill(random(255), random(255), random(255), 80);
      ellipse(mouseX, mouseY, 30);
    }
    function windowResized() {
      resizeCanvas(windowWidth, windowHeight);
    }
  </script>
</body>
</html>
```

## Pitfalls

- **Pin to `p5@1.11`**, not `@latest` or `@2`. p5 v2 replaced `preload()`
  with `async setup()`; the official p5 Editor still defaults to 1.x
  until at least August 2026, and most tutorials assume 1.x. Loading
  images/sounds in v2 without async-aware code silently breaks.
- **Global mode only works with one sketch per page.** A second
  `setup()`/`draw()` (e.g. an inline script alongside an external one)
  overwrites the first. Use **instance mode** (`new p5(p => { … })`)
  when there's more than one.
- **`preload()` is the only safe place to call `loadImage()` /
  `loadSound()` / `loadJSON()`.** Loading in `setup()` returns
  not-yet-ready objects, and `draw()` runs before they finish — kid
  sees a blank canvas with no error. Always:

  ```js
  let img;
  function preload() { img = loadImage("cat.jpg"); }
  function setup()   { createCanvas(400, 400); image(img, 0, 0); }
  ```

- **Asset paths are relative.** `loadImage("cat.jpg")` works,
  `loadImage("/cat.jpg")` 404s under the preview subpath.
- **`p5.sound` is a separate file.** If the kid wants sound:
  `<script src="https://cdn.jsdelivr.net/npm/p5@1.11/lib/addons/p5.sound.min.js"></script>`
  *after* the main p5 script.
- **An infinite loop in `draw()` will freeze the tab.** Don't write
  `while (…)` in `draw()` — p5 calls `draw()` 60 times a second; loops
  belong inside that, not around it.
- **`createCanvas` appends to `<body>`.** If the kid wants the canvas
  inside a specific element, pass a parent: `createCanvas(w, h).parent("main")`.
- **`keyPressed()` / `keyIsDown()` need a focused window.** Your sketch
  runs inside an iframe; p5 listens at the window level, which only fires
  when the iframe has keyboard focus. The host SPA focuses you on load
  and forwards arrow keys / Space / WASD even when focus is elsewhere —
  so arrow-key controls work without the kid needing to tap the canvas
  first. But: prefer on-screen buttons over keyboard as the *primary*
  control surface, because phones have no arrow keys and most kids test
  on phones first. Add keyboard as a desktop bonus.
